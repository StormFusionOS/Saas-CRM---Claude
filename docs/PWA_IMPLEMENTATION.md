# Progressive Web App (PWA) Implementation

## Overview

The StormFusion OS CRM has been enhanced with comprehensive Progressive Web App capabilities, enabling offline functionality, app installation, push notifications, and an improved mobile experience.

## Architecture

### Service Worker
- Auto-generated by `vite-plugin-pwa` using Workbox
- Implements intelligent caching strategies for different resource types
- Handles offline requests and background synchronization
- Automatically updates when new versions are deployed

### Manifest
Located in `vite.config.ts`, the manifest defines:
- App name: "StormFusion OS - CRM Portal"
- Theme colors matching the brand (#005AE0)
- Display mode: standalone (full-screen app experience)
- Icons for various sizes (192x192, 512x512)
- Shortcuts for quick access to Leads and Dashboard
- Screenshots for app store listings

## Features Implemented

### 1. Install Prompt (`PWAInstallPrompt`)
**Location**: `crm/src/components/pwa/PWAInstallPrompt.tsx`

- Detects if the app can be installed
- Shows install banner after 30 seconds of use
- Respects user dismissal for 7 days
- Handles both Android and iOS install flows
- Styled with glassmorphism design matching the UI

**User Experience**:
- Non-intrusive bottom-right notification
- "Install" button triggers native install dialog
- "Not now" button dismisses for 7 days
- Automatically hides once installed

### 2. Update Notification (`PWAUpdatePrompt`)
**Location**: `crm/src/components/pwa/PWAUpdatePrompt.tsx`

- Detects when new app version is available
- Shows update prompt at top-right
- Allows users to reload and get latest version
- Shows "Ready for offline use" message when first cached
- Checks for updates every hour automatically

**User Experience**:
- Green notification indicates new version available
- One-click "Reload" button applies update
- Gracefully handles update process

### 3. Offline Detection (`OfflineIndicator`)
**Location**: `crm/src/components/pwa/OfflineIndicator.tsx`

- Monitors real network connectivity
- Shows warning banner when offline
- Displays reconnection message with downtime
- Performs periodic connectivity checks (every 30s)
- Handles both browser API and real network checks

**User Experience**:
- Yellow banner appears when connection lost
- Shows "Offline - Working in offline mode" message
- Green "Back online" message with downtime when reconnected
- Auto-dismisses after 5 seconds

### 4. Background Sync
**Location**: `crm/src/lib/pwa/backgroundSync.ts`

Queues failed API requests for automatic retry when connection restored.

**Features**:
- Automatic request queuing when offline
- Retry logic with exponential backoff
- Max 3 retry attempts per request
- Persists queue in localStorage
- Fires custom events for sync success/failure
- Processes queue when coming back online

**Usage Example**:
```typescript
import { queueRequest } from '@/lib/pwa/backgroundSync';

// Queue a request when offline
await queueRequest('/api/v1/leads', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify(leadData)
});

// Listen for sync events
window.addEventListener('sync-success', (e) => {
  console.log('Synced:', e.detail);
});
```

### 5. Push Notifications (Skeleton)
**Location**: `crm/src/lib/pwa/pushNotifications.ts`

Provides foundation for web push notifications.

**Ready to Use**:
- Permission request handling
- Subscription management
- Local notification display
- iOS and Android compatibility checks

**Requires Configuration**:
```typescript
// Set your VAPID public key
const vapidPublicKey = 'YOUR_VAPID_PUBLIC_KEY_HERE';

// Backend endpoint to save subscription
await fetch('/api/v1/push/subscribe', {
  method: 'POST',
  body: JSON.stringify(subscription)
});
```

## Caching Strategy

### Static Assets (CacheFirst)
- **Fonts**: Cached for 1 year
- **Images**: Cached for 30 days, max 100 entries
- **Icons/SVG**: Included in precache

### API Requests (NetworkFirst)
- **Leads API**: 5 minute cache, 10s network timeout
- **Quotes/Customers/Invoices**: 5 minute cache, 10s network timeout
- Falls back to cache when offline
- Maximum 50-100 cached entries

### Authentication (NetworkOnly)
- Never cached for security
- Always fresh from network

### External Resources (CacheFirst)
- Google Fonts: Cached for 1 year
- CDN assets: Long-term caching

## Custom Hooks

### `usePWAInstall()`
**Location**: `crm/src/hooks/usePWA.ts`

```typescript
const {
  isInstallable,    // Can the app be installed?
  isInstalled,      // Is it already installed?
  promptInstall,    // Function to trigger install dialog
  dismissPrompt     // Function to dismiss prompt
} = usePWAInstall();
```

### `usePWAUpdate()`
**Location**: `crm/src/hooks/usePWA.ts`

```typescript
const {
  needRefresh,           // Is update available?
  offlineReady,          // Is app cached and ready?
  updateServiceWorker    // Function to apply update
} = usePWAUpdate();
```

### `useOnlineStatus()`
**Location**: `crm/src/hooks/useOnlineStatus.ts`

```typescript
const {
  isOnline,      // Current network status
  wasOffline,    // Just came back online?
  downtime       // How long was offline (ms)
} = useOnlineStatus();
```

## Integration

The PWA functionality is integrated via `PWAProvider`:

```tsx
// In App.tsx
<AuthProvider>
  <PWAProvider>
    <Routes>
      {/* Your routes */}
    </Routes>
  </PWAProvider>
</AuthProvider>
```

This ensures:
- Install prompt shown to eligible users
- Update notifications appear when needed
- Offline indicator tracks connectivity
- Background sync initialized on startup

## Development Mode

PWA features are enabled in development:
```typescript
devOptions: {
  enabled: true,
  type: 'module',
  navigateFallback: 'index.html'
}
```

This allows testing PWA features during development without building for production.

## Testing PWA Features

### Install
1. Open app in Chrome/Edge
2. Wait 30 seconds or trigger manually
3. Click "Install" in the prompt
4. App appears in app drawer/home screen

### Offline Mode
1. Open DevTools Network tab
2. Set throttling to "Offline"
3. Navigate the app
4. See offline indicator and cached pages

### Updates
1. Make code changes and rebuild
2. Service worker detects new version
3. Update prompt appears
4. Click "Reload" to update

### Background Sync
1. Go offline
2. Submit a form (e.g., create lead)
3. Request queued automatically
4. Go back online
5. Request automatically syncs

## Troubleshooting

### Service Worker Not Updating
```javascript
// Force update in console
navigator.serviceWorker.getRegistrations()
  .then(regs => regs.forEach(reg => reg.unregister()));
```

### Clear All Caches
```javascript
// In console
caches.keys().then(keys =>
  Promise.all(keys.map(key => caches.delete(key)))
);
```

### Debug Mode
Check PWA capabilities:
```javascript
// Open console after app loads
// PWA capabilities logged automatically
```

## Security Considerations

1. **HTTPS Required**: PWAs only work over HTTPS (or localhost)
2. **Token Storage**: Auth tokens stored in memory, not in cache
3. **API Requests**: Auth endpoints never cached
4. **Sensitive Data**: No PII stored in service worker cache
5. **Update Mechanism**: Automatic updates prevent serving stale vulnerable code
